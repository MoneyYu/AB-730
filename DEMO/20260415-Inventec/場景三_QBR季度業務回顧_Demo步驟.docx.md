# 場景三：客戶專案季度業務回顧 (QBR)
## Dell 2025 年度 QBR 準備與執行

---

## 場景背景（開場白）

> 各位學員，進入場景三。英業達需要在 2026/1/15 向品牌客戶 Dell 進行 2025 年度的季度業務回顧 (QBR)。由 Dell Server & Networking BU 的 VP — Michael Thompson 主持。
>
> 這次 QBR 特別緊張：Q3-Q4 ProServer X100 的交期從 97.5% 降到 91.3%，DPPM 從 150 升到 280，客戶已經明確表達 concern，威脅要增加第二供應商。
>
> PM James Chen 需要帶領團隊在三週內完成所有 QBR 準備工作——從數據彙整、KPI 分析、品質報告，到最終的客戶簡報。
>
> 這個場景展示 Copilot 如何幫助團隊在高壓下協同準備，並透過 Cowork 一次搞定端到端的自動化工作流程。

**涉及角色**：PM（主導簡報）、SCM（交期數據）、QA（品質報告）、IT（數據彙整）、BPM（流程改善）
**使用的範例檔案**：
- 英業達_QBR_KPI_Dashboard.xlsx
- 英業達_QBR準備郵件串.docx
- 英業達_QBR預演會議逐字稿.docx
- 英業達_會議總結範本.docx

## Demo QBR-Teams：QBR 預演會議的完整生命週期（會前→會中→會後）
**交付物**：會前議程 + 會中 Facilitator 筆記 + 會後多角度摘要 + 正式會議紀錄
**預計時間**：30-40 分鐘
**對應模組**：模組 5（管理會議與協作）
**範例資料**：**英業達_QBR預演會議逐字稿.docx**（6 人、52 分鐘完整逐字稿，含副總模擬客戶質詢）

### ── 會前準備（8 分鐘）──

#### 步驟 1：用 Copilot Chat 準備 QBR 預演會議（5 分鐘）

1. 開啟 Copilot Chat（Work 模式）
2. 輸入以下提示：
   ```
   我今天下午 2 點要主持 Dell QBR 的內部預演 (dry run) 會議。
   正式 QBR 是 1/15，由 Dell VP Michael Thompson 主持。

   請幫我準備：

   1. 搜尋 /英業達_QBR_KPI_Dashboard.xlsx，彙整最關鍵的 KPI 數字：
      - Q4 vs Q1 的交期達成率變化
      - DPPM 惡化趨勢
      - 成本節省達成率

   2. 搜尋 /英業達_QBR準備郵件串.docx，確認各部門的準備進度：
      - 誰已經交了資料？誰還沒交？

   3. 列出今天預演的議程建議

   4. 預測 Dell VP 最可能問的 5 個刁鑽問題，幫我準備回答要點

   用條列格式，讓我 5 分鐘內掌握全貌。
   ```
3. 展示 Copilot 跨兩份檔案彙整的結果

> 💡 **教學 Tip**：QBR 預演的目的不只是走一遍簡報，更重要的是**預判客戶會問什麼**。Copilot 幫你基於數據產生可能的刁鑽問題。

#### 步驟 2：用 Outlook 發預演提醒（3 分鐘）

1. 在 Outlook 中使用 Copilot：
   ```
   草擬一封會前提醒郵件給 Lisa Wang, Amy Hsu, Tom Lin, Sarah Chang, Robert Tsai。

   主旨：【今日 14:00】Dell QBR 預演 — 請準備以下資料

   內容：
   1. 今天 Robert 副總會扮演 Dell VP 的角色質詢我們
   2. 請各位準備：
      - Lisa：交期 root cause 分析的最終版
      - Amy：9 件客訴的最新 8D 狀態（特別是 NIC 問題的 Plan B）
      - Tom：成本節省數據（建議拆分正常節省 vs 異常成本）
      - Sarah：流程改善 ROI 計算
   3. 帶上任何可能被客戶追問的補充數據

   語氣緊張但有幹勁。
   ```

### ── 會中協作（10 分鐘）──

#### 步驟 3：啟用 Facilitator 追蹤預演（3 分鐘）

1. 加入 Teams 會議，開啟 Notes 面板
2. 在會議聊天中輸入：
   ```
   @Facilitator 今天的 Dell QBR 預演會議議程如下：
   1. 簡報走演 (40 min)
   2. Robert 副總模擬客戶 Q&A (20 min)
   3. 修改討論 (20 min)
   4. 行動項目確認 (10 min)

   請特別記錄：
   - Robert 副總（扮演客戶）提出的每一個問題
   - 我們的回答是否令人滿意
   - 簡報中需要修改的地方
   ```

#### 步驟 4：會中使用 Facilitator 記錄回饋（5 分鐘）

模擬預演進行（參考 **英業達_QBR預演會議逐字稿.docx** 口述）：

**記錄修改建議**
```
@Facilitator 修改項目：Lisa 建議 Executive Summary 改用「挑戰與改善」框架，
不要用對比方式呈現壞消息。
```

**記錄客戶模擬 Q&A**
```
@Facilitator 模擬客戶問題：Robert（扮演 Michael）問「10 月 88.5% 那個月發生什麼事？」
James 的回答：DRAM 來料品質問題影響 380 台。
Robert 的評價：回答可以，但要更簡短，客戶要聽怎麼確保不再發生。
```

**記錄預演結論**
```
@Facilitator 行動項目：
1. James — 修改 Executive Summary 措辭 — 1/7 前
2. Lisa — 加入 before/after 比較圖 — 1/8 前
3. Amy — 準備 NIC Plan B talking points — 1/8 前
4. Tom — 成本節省拆分呈現 — 1/7 前
5. Sarah — 突出 ROI 275% — 1/7 前
6. James — Q&A 應對手冊 15 題 — 1/10 前
7. Lisa — 跟 Dell Jennifer 探口風 — 1/10 前
8. James — 1/12 final dry run — 1/12
```

#### 步驟 5：會中私下用 Copilot 查數據（2 分鐘）

在 Copilot 側邊面板（私密）：
```
Robert 問「你的競爭對手 Foxconn 交期 98.2%」。
請搜尋公開資訊：2025 年台灣主要 ODM 廠的伺服器交期表現，
幫我準備一個反駁論點——我們的正常水準也是 96-97%。
```

### ── 會後產出（12-15 分鐘）──

#### 步驟 6：AI Summary + 多角度摘要（8 分鐘）

**副總角度（通知 CEO 用）**

在 Copilot Chat 中貼入 **英業達_QBR預演會議逐字稿.docx** 的內容，輸入：
```
請用「製造副總 Robert Tsai」的角度摘要這場 QBR 預演會議。
他要跟 CEO 報告預演結果和 QBR 的準備狀態。

格式：
🚦 QBR 準備狀態：🟢🟡🔴
📋 簡報品質評估：（一句話）
⚠️ 最大風險點：（客戶最可能追問的議題）
✅ 已準備好的：（有信心的部分）
❌ 還需要補強的：（修改項目清單）
📅 正式 QBR：1/15
```

**PM 角度（行動追蹤用）**
```
用 PM James Chen 的角度摘要。我需要追蹤所有的修改行動項目：

格式：
一、預演中發現的簡報問題（8 個修改項目）
二、模擬 Q&A 中暴露的弱點和回答改進
三、每個修改的負責人和截止日（表格）
四、1/12 final dry run 的檢查清單
```

**QA 角度（Amy 要知道她的待辦）**
```
用 QA Amy Hsu 的角度摘要預演會議。只保留跟 Amy 有關的：
✅ 我在預演中報告的內容被如何評價
❌ Robert 副總對我的回答有什麼修改建議
📋 我的修改待辦：NIC Plan B talking points
⏰ 截止日：1/8
```

#### 步驟 7：用 Word 產出正式的預演會議紀錄（4 分鐘）

1. 開啟 Word，使用 Copilot：
   ```
   請根據 /英業達_QBR預演會議逐字稿.docx，
   產出一份「QBR 預演回饋紀錄」，格式如下：

   英業達股份有限公司
   Dell QBR 2025 — 內部預演回饋紀錄

   一、預演概要（日期/出席者/簡報走演完成度）
   二、副總模擬客戶的 4 個問題 + 我們的回答 + 評價
   三、簡報修改項目清單（8 項，含負責人和截止日）
   四、Q&A 應對準備狀態
   五、正式 QBR 前的 checklist

   語氣內部用，不需要太正式，重點是行動追蹤。
   ```
2. 展示 Copilot 從逐字稿產出的預演紀錄

#### 步驟 8：產出 Q&A 應對手冊（3 分鐘）

```
根據 /英業達_QBR預演會議逐字稿.docx 中 Robert 副總模擬客戶問的 4 個問題，
加上 /英業達_QBR_KPI_Dashboard.xlsx 的數據，
幫我產生一份完整的 Q&A 應對手冊，包含：

Robert 已問的 4 題 + 額外 11 題可能被問的問題 = 共 15 題。

每題格式：
❓ 問題：[客戶可能的原話]
🎯 30 秒回答：[簡短版，適合當場回覆]
📝 詳細回答：[如果客戶追問的完整版]
📊 支撐數據：[引用哪個數字/圖表]
⚠️ 地雷：[這題不要提到什麼]

問題類型包含：
1-4: 預演中已問的（含改善後的回答）
5-7: 數字追問型
8-9: 競爭對手比較型
10-11: 承諾追蹤型
12-13: 未來計畫型
14-15: 威脅/談判型

產出 Word 文件，列印後帶進 QBR 會場。
```

> 🎯 **會後 Takeaway**：
> - QBR 預演的逐字稿是最珍貴的素材——副總的模擬質詢 = 真正客戶會問的問題
> - 從預演紀錄自動產出 Q&A 應對手冊（15 題）
> - 修改行動追蹤一目瞭然
> - 所有內容都從 **英業達_QBR預演會議逐字稿.docx** 這一份預建檔案產出

## Demo 4：Copilot Cowork — 端到端自動化工作流程
**交付物**：自動完成寄信 + 建簡報 + 排會議 + 發 Teams 訊息
**預計時間**：25-30 分鐘
**對應模組**：模組 2（Copilot Chat）+ 模組 6（定義 Copilot 角色）

### 教學重點先說明（5 分鐘）

在開始 Demo 前，先向學員說明 **Copilot Chat** vs **Cowork** 的核心差異：

| | Copilot Chat | Copilot Cowork |
|---|---|---|
| 做什麼 | 回答問題、產生內容 | **真的幫你做事** |
| 行動能力 | ❌ 不能寄信、排會議 | ✅ 寄信、排會議、建檔案、發 Teams |
| 審核機制 | 無（直接給你結果） | ✅ 每個動作都要你 Approve |
| 風險等級 | 低（只是文字回答） | 中-高（會實際執行動作） |
| Skills | 通用 AI 對話 | 13 種專業 Skills（Word/Excel/PPT/Email/Calendar...） |
| 適合用途 | 查資料、寫內容 | 批次自動化、端到端工作流程 |

```
🧠 Copilot Chat = 你的大腦（想、分析、寫）
🤖 Copilot Cowork = 你的雙手（做、執行、行動）
```

> ⚠️ **重要提醒**：Cowork 目前是 **Frontier Preview**，需要租戶加入 Frontier 計畫。如果學員的環境沒有 Cowork，可以用老師的環境 Demo，或用截圖/錄影展示。

### 步驟 1：開啟 Cowork（2 分鐘）

1. 開啟 Microsoft 365 Copilot（https://m365.cloud.microsoft）
2. 在左側導覽列找到 **Agents** → **All agents**
3. 搜尋 **「Cowork」**，點擊進入
4. 如果是第一次使用，選擇 **Add**
5. 進入 Cowork 介面：看到聊天輸入框、建議提示、最近任務

> 💡 **教學 Tip**：也可以在 Teams 中使用 Cowork——在右側導覽列 → Open Agents and bots → 搜尋 Cowork。

### 步驟 2：輸入完整的多步驟任務（5 分鐘）

1. 在 Cowork 的聊天輸入框中，輸入以下完整任務描述：
   ```
   我需要準備 Dell 的 2025 年度季度業務回顧 (QBR)，會議日期是 2026/1/15。
   請幫我完成以下工作：
   
   1. 搜尋我 OneDrive 中的「英業達_QBR_KPI_Dashboard」Excel 檔案
   
   2. 根據這份 Excel 的數據，建立一份 QBR 簡報 (PowerPoint)，包含：
      - 封面：英業達 x Dell 2025 年度業務回顧
      - Executive Summary：整體表現摘要（含出貨量、營收、品質、交期的 headline 數字）
      - 各產品線績效：ProServer X100、CloudBook L15、IoT Gateway G3
      - 品質改善措施：DPPM 趨勢和改善行動
      - 交期回顧：月度達成率趨勢和 root cause
      - 成本節省成果：實績 vs 目標
      - 2026 展望與承諾
   
   3. 草擬一封郵件給 Dell 的 Michael Thompson (michael.thompson@dell.com)，
      確認 1/15 的 QBR 會議議程，附上我們準備的議題清單，
      語氣專業但友善。
   
   4. 在 Teams 的 #Dell-QBR 頻道發布一則訊息，
      通知團隊 QBR 準備的最新進度，
      提醒各負責人在 12/30 前提交各自的數據和報告。
   
   5. 安排一場內部預演會議 (dry run)，
      日期 2026/1/5 下午 2 點，時長 90 分鐘，
      邀請 Lisa Wang, Amy Hsu, Tom Lin, Sarah Chang，
      會議主題：「Dell QBR 2025 內部預演」。
   ```
2. 按下 **Send**

> 💡 **教學 Tip**：Cowork 支援最多 16,000 字元的輸入——不要怕寫太多。越詳細越好。也可以附加檔案（拖曳或點擊附件按鈕）。

### 步驟 3：觀察 Cowork 的工作過程（8 分鐘）

1. 送出後，觀察 Cowork 的處理流程：

   **第一步：Thinking indicator**
   - Cowork 顯示「正在分析你的需求...」
   - 它在理解你的多步驟任務並規劃執行順序

   **第二步：Skill 載入**
   - 看到側邊面板顯示正在載入的 Skills：
   - 🔍 **Enterprise Search** — 搜尋 OneDrive 中的 Excel 檔案
   - 📊 **PowerPoint** — 準備建立簡報
   - 📧 **Email** — 準備寄送郵件
   - 💬 **Teams** — 準備發送頻道訊息
   - 📅 **Scheduling** — 準備排會議

   **第三步：逐步執行**
   - Cowork 會逐步執行每個任務
   - 每個步驟都會顯示：正在做什麼、進度、預覽

2. 展示 Cowork 的即時工作流程，強調它不是「一次給你全部結果」，而是**一步步做，讓你跟著看**

### 步驟 4：逐步 Approve 每個動作（8 分鐘）

每個會實際影響外部的動作，Cowork 都會暫停等你核准：

**Approve 1 — 簡報建立**
1. Cowork 展示簡報預覽（側邊面板）
2. 檢查投影片內容是否正確
3. 注意 **風險指示器**：建立文件是 Low Risk
4. 點擊 **Create** 按鈕確認
5. 或點擊下拉箭頭 → **Don't ask again**（本次對話中不再詢問類似動作）

**Approve 2 — 郵件發送**
1. Cowork 展示郵件預覽（收件人、主旨、內文）
2. ⚠️ 注意風險指示器：**發送郵件是 Medium Risk**
3. 仔細檢查：
   - 收件人是否正確？
   - 內容是否有不適當的措辭？
   - 有沒有洩漏敏感資訊？
4. 如果需要修改，可以直接在聊天中告訴 Cowork：
   ```
   請把郵件中的議程順序調整一下，先放品質再放交期
   ```
5. 確認無誤後，點擊 **Send**

**Approve 3 — Teams 訊息**
1. Cowork 展示即將發送到 Teams 頻道的訊息預覽
2. 檢查頻道是否正確、訊息內容是否得體
3. 點擊 **Post**

**Approve 4 — 會議排程**
1. Cowork 展示會議邀請預覽：
   - 主題、日期時間、邀請對象、會議描述
2. 檢查所有人的行事曆是否有衝突（Cowork 會自動檢查）
3. 點擊 **Schedule**

> 💡 **教學 Tip**：強調 Cowork 的安全設計——**永遠不會在你不知情的情況下採取行動**。每個有影響的動作都需要你明確核准。這跟「自動化」不同——Cowork 是「半自動化」，你是最後的守門人。

### 步驟 5：檢視成果與後續管理（3 分鐘）

1. 在右側面板檢視所有產出的文件：
   - 📊 PowerPoint 簡報 → 可以直接下載或在 OneDrive 中開啟
   - 📧 已發送的郵件 → 可以在 Outlook 的寄件備份中找到
   - 💬 Teams 訊息 → 已發布到 #Dell-QBR 頻道
   - 📅 會議邀請 → 已發送給所有受邀者

2. 切換到 **Tasks** 檢視：
   - 看到剛才完成的所有工作項目
   - 可以切換 **List view** / **Kanban board**
   - 每個任務顯示狀態：Done / In progress / Failed

3. 示範 **Scheduled** 分頁：
   - 可以設定 Cowork 的排程任務
   - 例如：每週一自動產生 Dell 客戶的郵件摘要報告

### 步驟 6：示範 Pause / Resume / Cancel（2 分鐘）

1. 說明在 Cowork 工作過程中，你可以隨時：
   - **Pause**：暫停當前任務（完成目前步驟後暫停，或立即暫停）
   - **Resume**：恢復已暫停的任務
   - **Cancel**：取消整個任務
2. 也可以隨時在聊天中插入新的指示來調整 Cowork 的行為：
   ```
   等一下，簡報先不要建立。我想先修改議程順序再產出簡報。
   ```

> 🎯 **本 Demo 學員 Takeaway**：
> - Cowork 是真正的「數位助理」——不只回答問題，還幫你做事
> - 一次描述多步驟任務，Cowork 自動拆解並逐步執行
> - 每個動作都需要你 Approve（安全控管）
> - 13 種內建 Skills 覆蓋常見辦公場景
> - Tasks 檢視幫你管理所有已完成的工作

## Demo 7：Outlook — QBR 郵件摘要與排程提示
**交付物**：郵件串摘要 + 自動化日報
**預計時間**：15 分鐘
**對應模組**：模組 2（Copilot Chat）+ 模組 3（草擬商業內容）

### 前置準備

## 加碼實戰情境：QBR 前後的真實戰場

以下是 PM/BPM/IT 在準備和執行客戶 QBR 時實際會遇到的高頻情境。每個都有完整的 Copilot 操作步驟。

---

### 實戰情境 A：QBR 當天客戶突然追問，你沒準備的數據

> **背景**：QBR 進行到一半，Dell VP Michael Thompson 突然問：「你們 ProServer X100 的 First Pass Yield 過去四季是多少？跟你們 CloudBook L15 的 FPY 比起來如何？我想了解是不是 Server 產線的整體能力有問題。」
>
> 你的簡報裡沒有 FPY 數據。會議室裡 20 個人看著你。
>
> **痛點**：你需要在 30 秒內做出反應——要不是當場查到數據，就是優雅地承諾會後補充。

**步驟 1 — 用手機/筆電私下問 Copilot in Teams**

在會議的 Copilot 側邊面板中（只有你看到），輸入：
```
Michael 剛問了 First Pass Yield 的數據。
請搜尋我的 OneDrive 和郵件中，有沒有包含 ProServer X100 和 CloudBook L15 的 FPY 數據？
也搜尋 Teams 頻道中有沒有人提過 FPY 或良率的數字。
```

**步驟 2 — 如果找到，直接回覆**

如果 Copilot 找到數據：
```
請把找到的 FPY 數據整理成一個簡單的比較表，我要直接唸出來：
ProServer X100: Q1 ___ / Q2 ___ / Q3 ___ / Q4 ___
CloudBook L15:  Q1 ___ / Q2 ___ / Q3 ___ / Q4 ___
```

**步驟 3 — 如果沒找到，用 Copilot 準備優雅的回應**

```
客戶問了我沒準備的 FPY 數據。幫我準備一段 30 秒的回應，內容：
1. 承認我今天的簡報沒有包含 FPY 數據
2. 說明我們有在追蹤這個指標
3. 承諾在本週五前提供完整的 FPY 趨勢分析
4. 順帶把話題帶回我們已經準備好的 DPPM 改善措施

語氣坦然自信，不要顯得慌張。
```

**步驟 4 — 會後用 Copilot 快速補資料**

回到辦公室後，在 Outlook 中：
```
請草擬一封 follow-up 郵件給 Dell 的 Michael Thompson，
主旨：ProServer X100 FPY Data — Follow-up from QBR

內容：
1. 感謝今天的 QBR 會議和寶貴的回饋
2. 附上他詢問的 FPY 數據：[插入 Excel 表格]
3. 簡要分析 FPY 與 DPPM 的相關性
4. 重申我們 Q1 2026 的品質改善承諾

語氣感謝且專業。英文。
```

> 💡 **教學 Tip**：QBR 被問到沒準備的問題是家常便飯。Copilot in Teams（私密的）讓你可以在會議中「偷偷查資料」，而不用當著客戶的面翻電腦。即使找不到，Copilot 也能幫你準備一段得體的回應。

---

### 實戰情境 B：客戶要求一週內提交改善計畫書

> **背景**：QBR 結束後，Michael Thompson 說：「我對你們 Q3-Q4 的表現很不滿意。請在一週內提交一份 Corrective Action Plan，涵蓋品質和交期。如果計畫不夠有說服力，我們會開始評估第二供應商。」
>
> **痛點**：你有一週時間，需要跨部門收集資訊、寫出一份能說服 VP 層級的改善計畫書。這份文件直接影響英業達能不能保住這個客戶。

**步驟 1 — 用 Cowork 一次展開所有準備工作**

在 Cowork 中：
```
我需要在一週內向 Dell 提交一份 Corrective Action Plan。請幫我做以下事情：

1. 草擬一封郵件給團隊（Lisa Wang, Amy Hsu, Tom Lin, Sarah Chang），
   說明客戶的要求和一週的截止日，分配以下工作：
   - Amy：品質異常的完整 8D 報告更新 + 預防措施
   - Lisa：交期改善措施 + 供應鏈強化計畫
   - Sarah：流程改善提案 + 投資計畫
   - Tom：歷史數據和趨勢分析支援
   截止日：3 天後交初稿

2. 安排一場明天早上 9 點的緊急會議，30 分鐘，
   主題「Dell Corrective Action Plan 啟動會議」

3. 在 Teams #Dell-QBR 頻道發布訊息，通知團隊優先處理此案

4. 建立一份 Word 文件，標題「Dell Corrective Action Plan — Draft」，
   包含以下章節框架：
   - Executive Summary
   - Root Cause Analysis（品質 + 交期）
   - Corrective Actions（短期 0-30天 / 中期 30-90天 / 長期 90天+）
   - Prevention Measures
   - Investment Plan
   - Timeline & Milestones
   - KPI Targets for Q1 2026
```

**步驟 2 — 用 Word Copilot 撰寫改善計畫**

3 天後團隊交了初稿，在 Word 中使用 Copilot 整合：
```
請根據以下各部門的回報，撰寫 Corrective Action Plan 的完整內容：

品質改善（Amy 的回報）：
- GPU 散熱片組裝偏移：已導入定位治具，不良率從 4.5% 降至 0.3%
- BMC 韌體問題：v2.3.2 已釋出，正在 Dell 驗證中
- NIC 相容性：Broadcom firmware fix ETA 1 月中
- 預防措施：AI 視覺檢測導入、SPC 即時監控

交期改善（Lisa 的回報）：
- DRAM 安全庫存提升到 4 週
- NovaTech 產能保證合約已簽
- SiliconEdge 備援機制 Q1 完成
- 新增一條組裝線（投資 $1.2M，Q2 可用）

請把這些資訊整合成一份完整的 Corrective Action Plan，
每個改善措施都要包含：問題描述 → 根因 → 改善行動 → 負責人 → 完成日期 → 驗證方式
語氣誠懇但有信心，展現我們對改善的決心。英文撰寫。
```

**步驟 3 — 用 PPT Copilot 做一頁式摘要**

```
請根據剛才的 Corrective Action Plan，建立一頁式的 Executive Summary 投影片：

左半邊：Top 5 改善行動（含時程和負責人）
右半邊：Q1 2026 KPI 承諾
- 交期達成率：>97%（目前 91.3%）
- DPPM：<150（目前 280）
- 客訴關閉率：100%
下方：Investment commitment：$2.57M

這一頁要能讓 Dell VP 在 30 秒內理解我們的改善誠意和具體行動。
```

> 💡 **教學 Tip**：「一週內交改善計畫」是 ODM 最高壓的情境之一。Copilot 不能幫你做改善，但它能幫你**更快地把改善措施組織成有說服力的文件**。重點是：跨部門收集 → 整合 → 產出，每一步 Copilot 都能加速。

### 實戰情境 C：IT 角色 — 快速彙整 ERP 數據做 Dashboard

> **背景**：你是 IT 的 Tom Lin。James 說「我要全年度的出貨、營收、成本節省數據，格式要能直接做圖表。12/25 前給我。」
>
> **痛點**：ERP 匯出的原始資料又醜又亂，需要清理、轉換格式、加上公式。

**步驟 1 — 用 Excel Copilot 整理原始數據**

開啟 **英業達_ERP原始出貨記錄.xlsx**（含約 400 筆模擬出貨記錄，其中故意包含重複資料和日期格式不一致的記錄，供資料清理練習用），使用 Copilot：
```
這份資料是從 ERP 匯出的原始出貨記錄（英業達_ERP原始出貨記錄.xlsx），請幫我：
1. 移除重複的行
2. 把日期欄位統一為 YYYY/MM/DD 格式
3. 新增一欄「季度」（根據出貨日期自動判斷 Q1-Q4）
4. 新增一欄「產品類別」（根據料號前綴判斷：PS=ProServer, CB=CloudBook, IG=IoT Gateway）
5. 建立一個樞紐分析表：按季度 × 產品類別 彙總出貨量和金額
```

**步驟 2 — 用 Excel Copilot 建立 Dashboard 圖表**

```
根據剛才的樞紐分析表，建立以下圖表：
1. 月度出貨量趨勢折線圖（三條線代表三個產品）
2. 季度營收堆疊長條圖
3. 成本節省達成率的子彈圖（實績 vs 目標）

把三個圖表排列在同一個工作表中，看起來像一個 Dashboard。
```

**步驟 3 — 用 Outlook Copilot 發送數據**

```
請草擬一封郵件給 James Chen，
附上剛完成的 QBR Dashboard Excel 檔案。
內容簡要說明：
1. 數據來源：ERP 系統截至 12/24 的最新資料
2. 包含三個 Dashboard 圖表
3. 注意事項：12 月的數據尚未完全結算，最終數字可能微調
4. 如果需要其他維度的分析（如按客戶、按地區），我可以追加

語氣簡短專業。
```

> 💡 **教學 Tip**：IT 同仁常覺得 Copilot「跟我無關」。但 ERP 數據整理、格式轉換、Dashboard 建立，這些都是 IT 天天在做的事。Copilot 在 Excel 中的資料清理和圖表功能，對 IT 角色的時間節省非常顯著。

### 實戰情境 D：BPM 角色 — 流程改善提案簡報

> **背景**：你是 BPM 的 Sarah Chang。QBR 中客戶對品質很不滿意，你需要提出 2026 年的流程改善提案，包含投資金額和預期效益，說服管理層批准預算。
>
> **痛點**：你有改善的想法，但需要把它們「量化」和「可視化」，才能讓管理層願意批預算。

**步驟 1 — 用 Copilot Chat 做改善提案的 ROI 分析**

```
我計畫在 2026 年推動以下三個製造流程改善專案，請幫我計算每個的 ROI：

專案 1：AI 視覺品檢擴展到整機組裝段
- 投資：$600K（設備 + AI 模型訓練 + 部署）
- 預期效益：DPPM 降低 40%（從 280 降到 168），減少客訴處理成本
- 假設每件客訴的處理成本（含 rework + 運費 + 人力）約 $5,000

專案 2：SPC 即時監控系統
- 投資：$200K
- 預期效益：品質異常偵測時間從 4 小時縮短至 15 分鐘
- 假設每次延遲偵測造成的平均損失是 $25,000（不良品流出成本）

專案 3：Digital Twin 產線模擬
- 投資：$400K
- 預期效益：新機種量產準備時間縮短 25%
- 假設每縮短 1 週量產準備 = 節省 $50,000 產線閒置成本

請計算每個專案的：
1. 年度預期節省金額
2. 投資回收期（月）
3. 3 年 ROI
4. 優先順序建議

用表格呈現。
```

**步驟 2 — 用 PPT Copilot 建立投資提案簡報**

```
建立一份 6 頁的流程改善投資提案簡報，給製造副總 Robert Tsai：

1. 封面：2026 年製造流程改善投資提案
2. 背景與驅動力：Dell QBR 的品質 concern + 市場競爭壓力
3. 2025 年改善成果回顧（四大改善及量化成果）
4. 2026 年三大投資提案：
   - 每個提案一頁，含：問題 → 方案 → 投資 → 效益 → ROI → 時程
5. 總投資彙總：$1.2M，預計 3 年回收 $4.5M，ROI 275%
6. 請求核准 + 時程

風格：用數字說話，管理層喜歡看 ROI 和回收期。
每頁含講者備忘稿。
```

> 💡 **教學 Tip**：BPM 角色最大的挑戰是「把改善想法量化」。很多好的改善提案被管理層拒絕，不是因為想法不好，而是因為**沒有算清楚 ROI**。Copilot 可以幫你快速做 ROI 計算和視覺化。

### 實戰情境 E：QBR 會後的行動追蹤（每週 Follow-up）

> **背景**：QBR 結束後，你承諾了 15 個改善行動項目。Dell 的 PM Jennifer Walsh 每週五會 email 問你：「James，這週的 action items 進度如何？」你需要每週回覆一份進度更新。
>
> **痛點**：15 個 action items 分散在不同人手上，你要逐一追蹤再彙整。

**用排程提示 + Copilot 自動化追蹤**

設定排程提示：
```
每週四下午 3 點，請執行以下任務：

1. 搜尋 Teams 頻道 #Dell-QBR 本週的所有討論
2. 搜尋本週收到的來自 Lisa Wang, Amy Hsu, Tom Lin, Sarah Chang 的郵件中，
   跟「改善」「action item」「corrective action」「進度」相關的內容
3. 根據搜尋結果，產生一份 QBR Action Items 週報，格式：

| # | Action Item | Owner | Due Date | Status | 本週進展 |
|---|------------|-------|----------|--------|---------|

4. 在最後加上：
   - 本週完成的項目 ✅
   - 有延遲風險的項目 ⚠️
   - 需要 escalation 的項目 🔴

然後草擬一封英文郵件給 Dell 的 Jennifer Walsh，
附上這份進度更新，語氣積極正面。
```

然後你只需要每週四下午花 10 分鐘檢查 Copilot 產出的草稿，做小修改後發出。

> 💡 **教學 Tip**：QBR 後的 follow-up 才是真正的戰場。很多公司 QBR 做得很漂亮，但會後的 action tracking 虎頭蛇尾。Copilot 的排程提示讓你**永遠不會忘記每週更新**，而且彙整工作自動化了。

### 實戰情境 F：用 Copilot 準備 QBR 的「預演問答」

> **背景**：QBR 前一天的 dry run，你想預演客戶可能問的刁鑽問題。
>
> **痛點**：你自己想的問題太軟了，需要一個「扮演客戶」的角色來壓力測試你。

**讓 Copilot 扮演嚴厲的客戶 VP**

在 Copilot Chat 中：
```
請扮演 Dell 的 VP Michael Thompson。你對英業達 Q3-Q4 的表現很不滿意。
根據 /英業達_QBR_KPI_Dashboard.xlsx 的數據，
用嚴厲但專業的語氣問我 10 個刁鑽的問題。

問題類型包含：
1. 數字追問型：「你說 Q4 交期 91.3%，但我看你 10 月只有 88.5%，這個月發生了什麼？」
2. 比較型：「你的競爭對手 Foxconn 的交期都能維持在 98% 以上，為什麼你們做不到？」
3. 承諾追蹤型：「你去年 QBR 也承諾過要改善，現在反而更差了，我怎麼相信你這次會做到？」
4. 威脅型：「我們已經在評估第二供應商了，你有什麼理由讓我繼續把量給你？」
5. 細節挖掘型：「QA-2025-055 的 NIC 問題，Broadcom 到底什麼時候能給 fix？」

每個問題後面，也幫我準備建議的回答要點。
```

> 💡 **教學 Tip**：這是 Copilot 一個非常強大但容易被忽略的用法——**角色扮演和壓力測試**。讓 Copilot 扮演你的客戶、你的老闆、你的對手，提前預演困難的對話。比自己想「他會問什麼」有效 10 倍。
